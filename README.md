# 서울메이트 · 비짓서울 API 연동본

사용자가 올린 `gemini-code-1789032822330.html`을 기반으로 만들었습니다. `index.html`을 더블클릭하면 기존 온보딩부터 일정·여행 결산까지 이어집니다. 일정 체크리스트 바로 위에 날씨 카드가 있습니다. 원본 다운로드 파일은 수정하지 않았습니다.

## 지금 확인할 수 있는 화면

- 선택한 여행 지역, 기온, 강수 상태, 습도, 풍속, 1시간 강수량
- 관측 시각과 출처, 새로고침, 상황별 여행 안내
- ‘시연 날씨 바꿔보기’에서 강수 없음·비·눈 화면 선택
- 예시 날씨는 실제 관측값과 명확히 구분
- 일정 단계에서 비짓서울 공식 콘텐츠 목록·상세 API로 장소, 카테고리, 좌표, 주소, 운영시간, 대표사진을 불러오는 연결부
- 키가 없을 때에는 시연용 샘플만 표시하고, 실데이터와 섞지 않음

## 비짓서울 API 연결

비짓서울 문서의 `POST https://api-call.visitseoul.net/api/v1/contents/list`와 `POST https://api-call.visitseoul.net/api/v1/contents/info` 규격을 사용합니다. 인증 헤더는 `VISITSEOUL-API-KEY`이며 브라우저에는 키를 보내지 않습니다.

Render의 Environment Variables에 다음을 추가하세요.

`VISITSEOUL_API_KEY` = 발급받은 키

`VISITSEOUL_CACHE_TTL_MS` = `600000` (선택)

키가 설정되면 `/api/visit/recommend`가 사용자가 고른 8개 공식 카테고리와 권역을 기준으로 목록을 조회하고, 상세 API에서 좌표·사진·주소를 보강합니다. 이미 가본 장소의 Visit Seoul CID는 추천에서 제외합니다. 모든 장소 카드에는 `source: visitseoul`이 붙습니다.

하루 일정의 음식 장소는 별도 규칙으로 관리합니다. 비짓서울 `음식` 카테고리에서 최대 2곳만 선택하고 첫 번째는 13:00 점심, 두 번째는 18:00 저녁 슬롯에 배치합니다. 음식 데이터가 부족하면 없는 장소를 임의로 만들지 않고 실제 API 결과만 표시합니다.

GPS는 HTTPS 모바일 브라우저에서 권한을 허용하면 실제 위치를 기록합니다. 데스크톱이나 실내에서 위치 신호를 받을 수 없을 때에는 `시연용 이동 기록` 버튼으로 API 장소 좌표를 따라가는 시연 경로를 만들 수 있으며, 결산에는 시연 데이터라고 표시합니다.

API 키를 `index.html`, GitHub Pages, `.env.example`에 넣으면 안 됩니다. Render에 저장한 뒤 서비스를 재배포하면 됩니다.

## 키를 받으면 연결하는 방법

1. 공공데이터포털의 [기상청_단기예보 조회서비스](https://www.data.go.kr/data/15084084/openapi.do)를 신청합니다. 이 코드는 **data.go.kr 서비스키**용입니다. 기상청 API허브의 별도 인증키와는 다릅니다.
2. 이 폴더의 `.env.example`을 복사해 `.env` 파일을 만들고 `KMA_SERVICE_KEY=` 뒤에 일반 인증키(Decoding)를 넣습니다.
3. Node.js 22 이상에서 이 폴더를 열어 `npm start`를 실행합니다. 외부 패키지 설치는 필요 없습니다.
4. `http://127.0.0.1:3003`을 열고 일정을 시작합니다. 정상 응답을 받으면 ‘기상청 관측’으로 바뀝니다.

HTML을 더블클릭하는 방식은 시연용입니다. 실제 연동은 서버 주소에서 접속해야 합니다. 환경변수만 설정해도 서버가 키를 읽으며, 브라우저 코드나 GitHub 파일에 키를 넣을 필요가 없습니다. 키 설정 후에는 서버를 재시작하세요.

## GitHub에 올릴 때

이 폴더를 올리면 됩니다. `.gitignore`에 `.env` 제외 규칙이 있습니다. **실제 키를 index.html, README 또는 .env.example에 적지 마세요.** 이 작업에서는 GitHub 업로드나 외부 배포를 수행하지 않았습니다.

GitHub Pages에는 화면을 공개할 수 있지만 이 Node 서버는 실행할 수 없습니다. 실제 연동에는 Node 서버나 서버리스 함수가 동작하는 호스팅이 필요합니다. 같은 서버에서 화면과 `/api/weather`를 제공하는 구성을 권장합니다. 서버를 별도로 두면 HTML의 `window.SEOULMATE_WEATHER_ENDPOINT` 설정과 서버의 허용 출처(CORS)를 추가로 설정해야 합니다.

## 연결 구조와 범위

브라우저 → `/api/weather?region=hongdae` → 서버 환경변수 인증키 → 기상청 `getUltraSrtNcst` → 정리한 JSON → 날씨 카드.

- 기상청 초단기실황은 지역의 대표 관측값입니다. 초 단위 생중계가 아니므로 화면에 관측 시각을 표시합니다.
- 선택 여행 권역별 대표 격자를 사용합니다. 휴대폰 GPS를 추적하는 기능과는 독립적입니다. 권역은 넓어 내부 위치에 따라 날씨가 다를 수 있습니다.
- `T1H` 기온, `PTY` 강수 형태, `REH` 습도, `WSD` 풍속, `RN1` 1시간 강수량을 사용합니다. 강수가 없다는 이유로 ‘맑음’을 표시하지 않습니다. 구름 상태·강수확률·시간별 예보는 이번 범위에 없습니다.
- 한국 시간 기준 최근 정시 관측을 조회하며 45분 여유를 둡니다. 자료가 아직 없으면 최대 두 시간 이전 자료를 재조회합니다. 오래된 관측은 별도 표시합니다.
- 서버는 10분 캐시와 중복 요청 병합, 제한 시간을 적용합니다. 화면은 일정 단계가 열려 있을 때 10분마다 확인합니다.
- 연동 오류를 가짜 실시간 날씨로 대체하지 않습니다. 이전 관측을 유지할 때는 갱신 실패를 표시합니다.
- 키 미발급 상태이므로 실제 기상청 호출은 검증하지 않았습니다. 최초 발급 후 인증·사용 승인·실제 응답을 확인해야 합니다. 기존 LLM·관광 데이터 기능은 업로드된 원본의 상태를 유지합니다.
